# EntryRule

`EntryRule`은 신규 포지션을 열 조건을 판단한다. 이 레이어는 주문을 직접 넣지 않고, 진입 의도나 신호를 만든다.

초기 구현은 [거래 원칙](../../../trading-principles/README.md)에 따라 고가 돌파, 이동평균 위 가격, 거래량 증가처럼 차트에서 직접 확인 가능한 조건을 우선한다.

다중 타임프레임 전략에서는 [타임프레임 설계](../../timeframes/README.md)에 따라 상위 타임프레임으로 큰 방향을 확인하고, 진입 타임프레임으로 실제 진입 신호를 만든다.

## 핵심 질문

언제 들어갈까?

## 책임

- 시장 데이터와 현재 포트폴리오 상태를 보고 진입 후보를 만든다.
- 규칙별 파라미터를 명확하게 드러낸다.
- 동일 조건에서 항상 같은 신호를 생성한다.
- 진입 신호와 실제 주문 실행을 분리한다.

## 입력

- 유니버스에 포함된 종목 목록
- 일봉, 분봉, tick 같은 시장 데이터
- 전략 파라미터
- 현재 보유 여부
- 상위, 진입 타임프레임 데이터

## 출력

- 진입 신호
- 주문 의도
- 신호 발생 이유
- 신호 계산에 사용한 기준값

## 구현 후보

- 직접 구현: `EntryRule` 인터페이스와 `Signal` 또는 `OrderIntent` 모델은 프로젝트 도메인에 맞게 직접 정의해야 한다.
- [cinar/indicator](https://github.com/cinar/indicator): Go 기반 기술지표, 전략, 백테스트 도구를 제공하므로 지표 계산 후보로 조사할 만하다.
- [TA-Lib](https://ta-lib.org/): 오래된 기술적 분석 라이브러리로 지표 검증 기준이나 외부 바인딩 후보로 볼 수 있다.
- [Gonum](https://github.com/gonum/gonum): 통계, 행렬, 최적화 계산이 필요해질 때 사용할 Go 수치 계산 라이브러리 후보.

## 조사할 자료

- 터틀 트레이딩 돌파 진입 규칙
- 돈치안 채널, 이동평균, 거래대금 기반 진입 조건
- 미국 ETF에서 정규장과 장외 시간 돌파 신호를 구분하는 기준
- 신호 중복 방지와 재진입 제한 방식

## 설계 쟁점

- 신호를 `Signal`로 둘지, 바로 `OrderIntent`로 둘지 정해야 한다.
- 진입 규칙이 수량을 계산하지 않도록 경계를 지켜야 한다.
- 일봉 기준 신호와 분봉 기준 신호의 호출 시점을 분리해야 한다.
- 상위 타임프레임 조건이 깨졌을 때 하위 타임프레임 진입 신호를 무시할 수 있어야 한다.
- 같은 종목에서 여러 진입 규칙이 동시에 발생할 때 우선순위를 정해야 한다.
