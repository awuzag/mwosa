# UniverseSelector

`UniverseSelector`는 전략이 관찰할 종목 집합을 결정한다. 좋은 진입 규칙도 잘못된 유니버스 위에서는 거래정지, 유동성 부족, 관리종목 같은 문제에 끌려갈 수 있다.

## 핵심 질문

무엇을 볼까?

## 책임

- 전략 실행 전에 관찰 대상 종목을 좁힌다.
- 미국 ETF 거래 가능성에 맞는 기본 제외 조건을 적용한다.
- 일봉 전략과 분봉 전략이 사용할 후보군 크기를 다르게 제한한다.
- 특정 리서치 결과나 사용자 관심 종목 목록을 유니버스로 변환한다.

## 입력

- ETF 마스터
- 시장 구분
- 거래 가능 상태 정보
- AUM, 거래대금, 거래량, 스프레드 같은 필터용 지표
- 외부 리서치 결과나 사용자가 만든 후보군

## 출력

- 특정 실행 시점의 관찰 종목 목록
- 제외된 종목과 제외 사유
- 유니버스 생성에 사용한 기준

## 구현 후보

- 직접 구현: 유니버스 필터와 선정 규칙은 프로젝트의 전략 철학에 가까우므로 직접 구현하는 편이 좋다.
- [Alpaca Trading API](https://docs.alpaca.markets/): 미국 주식과 ETF 주문, 페이퍼 트레이딩, 자산 조회 연동 후보.
- [Interactive Brokers API](https://www.interactivebrokers.com/campus/ibkr-api-page/webapi-doc/): 미국 ETF 주문과 계좌 조회를 붙일 수 있는 브로커 API 후보.
- [go-playground/validator](https://github.com/go-playground/validator): 유니버스 조건 파일이나 설정 구조체 검증에 쓸 수 있는 Go 검증 라이브러리.

## 조사할 자료

- 미국 ETF 목록, AUM, 운용사, 추종 지수, 비용률 데이터 출처
- ETF 거래량, 거래대금, bid-ask spread, 상장 기간 필터 기준
- 레버리지, 인버스, 원자재, 채권 ETF를 기본 유니버스에 넣을지 여부
- 분봉 전략에서 현실적인 동시 감시 ETF 수
- 외부 스크리닝 결과를 유니버스로 가져오는 형식

## 설계 쟁점

- 유니버스를 매일 고정할지, 장중에도 갱신할지 정해야 한다.
- 백테스트에서 과거 시점의 유니버스를 재현할 수 있어야 한다.
- 생존자 편향을 줄이려면 상장폐지, 거래정지, 과거 종목 상태를 다뤄야 한다.
- 분봉 전략은 전체 종목을 보지 않고, 일봉 또는 장전 필터로 후보군을 줄이는 구조가 필요하다.
