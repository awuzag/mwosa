# PositionSizer

`PositionSizer`는 진입 또는 추가 진입 시 얼마나 살지 결정한다. 같은 신호라도 수량 계산 방식에 따라 전략의 위험과 수익 구조가 완전히 달라진다.

## 핵심 질문

얼마나 걸까?

## 책임

- 주문 후보의 수량 또는 금액을 계산한다.
- 계좌 규모와 종목 변동성을 반영한다.
- 최소 주문 단위, 현금 잔고, 호가 단위를 고려한다.
- 수량 계산 근거를 기록 가능하게 만든다.

## 입력

- 주문 의도
- 현재 포트폴리오와 현금
- 종목 가격과 변동성 지표
- 거래당 허용 위험 비율
- 전략별 포지션 사이징 파라미터

## 출력

- 주문 수량
- 주문 금액
- 계산 기준 위험 금액
- 수량 계산에 사용한 변동성 값

## 구현 후보

- 직접 구현: 고정 금액, 고정 비율, ATR/N 기반 수량 계산은 프로젝트의 핵심 규칙이므로 직접 구현해야 한다.
- [shopspring/decimal](https://github.com/shopspring/decimal): 달러 금액, 수수료, 환율, 세금 계산에서 부동소수점 오차를 피하기 위한 decimal 후보.
- [Gonum](https://github.com/gonum/gonum): 변동성, 표준편차, 리스크 분산 계산을 직접 만들 때 보조로 쓸 수 있다.
- [go-playground/validator](https://github.com/go-playground/validator): 포지션 사이징 설정값의 범위 검증에 사용할 수 있다.

## 조사할 자료

- 터틀 트레이딩의 `N` 기반 유닛 사이징
- ATR 기반 수량 계산
- 고정 금액, 고정 비율, 변동성 조정 방식 비교
- 미국 ETF 최소 주문 단위, fractional share 지원 여부, 주문 가능 금액 제약
- 피라미딩에서 추가 유닛 크기를 정하는 방식

## 설계 쟁점

- 수량 계산을 달러 금액으로 먼저 할지, share 수량으로 바로 할지 정해야 한다.
- 손절선이 없는 전략에서 거래당 위험을 어떻게 계산할지 정해야 한다.
- 포지션 사이징 결과가 리스크 한도를 넘으면 `RiskManager`가 축소할 수 있어야 한다.
- 분봉 전략에서는 가격 변동이 빠르므로 계산 기준 가격과 실제 체결 가격 차이를 고려해야 한다.
