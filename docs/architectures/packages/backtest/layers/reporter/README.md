# Reporter

`Reporter`는 백테스트, 페이퍼 트레이딩, 실거래 결과를 사람이 읽고 다시 판단할 수 있는 형태로 정리한다.

## 핵심 질문

결과가 좋았나, 나빴나?

## 책임

- 거래 결과와 계좌 변화를 기록한다.
- 수익률, 낙폭, 승률, 손익비 같은 성과 지표를 계산한다.
- 리스크 거절, 체결 실패, 데이터 품질 문제를 드러낸다.
- 사람과 AI 에이전트가 읽을 수 있는 출력 형식을 제공한다.

## 입력

- 포트폴리오 상태 변화
- 거래 내역
- 리스크 이벤트
- 주문 및 체결 로그
- 데이터 품질 경고

## 출력

- Markdown 리포트
- JSON 또는 CSV 결과
- 거래 로그
- 성과 요약
- 실패와 경고 목록

## 구현 후보

- 직접 구현: Markdown, JSON, CSV 출력은 Go 표준 라이브러리로 먼저 직접 구현하는 편이 단순하다.
- Go 표준 `encoding/json`, `encoding/csv`, `text/template`: 구조화 출력과 Markdown 리포트 생성을 위한 기본 후보.
- [Gonum](https://github.com/gonum/gonum): 수익률 분포, 변동성, 통계 지표 계산이 복잡해질 때 사용할 수 있다.
- [go-echarts](https://github.com/go-echarts/go-echarts): HTML 리포트나 간단한 차트 시각화를 붙일 때 조사할 후보.
- [Prometheus Go client](https://prometheus.io/docs/guides/go-application/): 실거래 운영 단계에서 봇 상태와 주문 처리 지표를 노출할 때 후보.

## 조사할 자료

- 백테스트 성과 지표: CAGR, MDD, 변동성, Sharpe, 승률, 손익비
- 월별 수익률과 종목별 기여도 표현 방식
- 사람이 읽는 리포트와 AI 에이전트가 읽는 구조화 출력의 분리
- 실거래 운영 로그와 감사 로그에 필요한 필드
- 사람이 읽는 리포트와 자동화가 읽는 machine-readable output의 분리 원칙

## 설계 쟁점

- Markdown은 사람용, JSON/CSV는 자동화용으로 분리하는 편이 좋다.
- 좋은 결과만 보여주지 말고 리스크 거절과 체결 실패를 함께 보여줘야 한다.
- 백테스트 조건, 데이터 범위, 체결 가정을 리포트에 반드시 포함해야 한다.
- 실거래에서는 주문 전 의도와 실제 체결 결과를 함께 남겨야 한다.
